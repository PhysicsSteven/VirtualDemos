# Languages on VirtualDemos (i18n)

Set up 2026-11-01 at Steve's request. English is the site's language and stays exactly as it was: with English chosen (the default)
no page changes at all. Other languages are added page by page from string catalogs. Spanish is a pilot on a few pages, machine
drafted and labeled as a draft until a fluent speaker (a TA, say) has reviewed the physics wording.

## How it works

- `demos/lib/theme.js` (on every page already) loads `demos/lib/i18n.js` right after itself. Nothing else needs linking.
- **The English text is the key.** After a page has built itself, `i18n.js` walks it once and replaces each piece of text that has a
  translation, then keeps translating text the page writes later (status lines, button labels, readouts), attributes (`title`,
  `aria-label`, `placeholder`, `alt`, `label`), canvas text (`fillText`, `strokeText`, `measureText`), `alert` and `confirm`, and the
  page title. It changes a text node's text, never the node, so a demo's own references to its elements keep working.
- **Runs with formatting.** Text with inline formatting is one key with bare tag names, for example
  `<b>Mass</b> of the bob`. The translation must keep the same tags in the same order (`<b>Masa</b> de la lenteja`); if it does
  not, the pieces are looked up one by one instead. `tools/i18n.cjs check` flags it.
- **Numbers.** A string with numbers is looked up as it is, then as a pattern with each number written `{#}`:
  `Settling {#} grains: {#} %`. The translation puts the numbers back in order (`{#}`) or by position (`{#2}`, `{#1}`). Numbers
  are written with the language's decimal mark (`decimal` in its `meta.json`). A number glued to letters (`CO2`, `3D`) is text.
- **Fallback.** Anything without a translation stays English. A page with no catalog in the chosen language stays all English,
  and its switch says the language is not on that page yet.
- **Choosing.** The language switch sits beside the theme switch on every page that has a translation (and on every page once a
  student has picked a language other than English, so they can switch back). The choice is saved in the browser (`vd-lang`) and
  can be set from a link with `?lang=es`. A draft language shows a small "draft" badge next to the switch with a note.
- **Worksheets.** Translation runs after `worksheet.js` has built the answer boxes (it reads the English headings), and MathJax
  waits for it (`_includes/head-custom.html`), so the math is typeset in the translated text. Saved answers and exports keep
  the worksheet's own keys; data table headings and CSV column names show translated.

## Files

| Path | What it is |
| --- | --- |
| `demos/lib/i18n.js` | the runtime; its `LANGS` block (written by `tools/i18n.cjs index`) lists each language and the pages it covers |
| `demos/lib/i18n/en/<page>.js` | the English strings harvested from each page (an array, in the order first seen); do not edit by hand |
| `demos/lib/i18n/en/common.js` | strings found on many demos (the framework, theme switch, navigation, shared buttons) |
| `demos/lib/i18n/<lang>/meta.json` | the language: `name` (as its speakers write it), `dir` (`ltr` or `rtl`), `decimal`, `draft` (badge text), `note` |
| `demos/lib/i18n/<lang>/<page>.js` | translations: English key, translation |
| `tools/i18n.cjs` | harvest, common, index, check, todo, merge |

Page names: `demo/<demo>`, `ws/<worksheet>`, `notes/<demo>`, `site` (home, course, topic, OpenStax pages and the notes index),
and `common`. A page's lookup tries its own catalog, then `common`, then `site`.

## Adding strings when you build or change a demo

Nothing special in the markup: write English as always. Then:

1. `NODE_PATH=/opt/node-tools/node_modules node tools/i18n.cjs harvest <demo>` (with `VD_THREE` set to a local three.min.js r128
   in the cloud container). It opens the demo, presses every Setups chip, switch segment and tab, plays for a moment, opens
   every fold and records every string shown. Commit the new `demos/lib/i18n/en/demo/<demo>.js`.
2. Check the harvest caught everything: open `demos/<demo>.html?lang=qps`. The test language shows every harvested string
   accented and about 40 % longer inside ⟦ ⟧. **Plain English that is still showing was never harvested** (a state the harvest
   did not reach). Visit that state and harvest again, or wrap the string as below. Long labels also show where a longer language
   would overflow.
3. Text built in code is caught as it is shown, so most code needs nothing. Two cases need care:
   - **Never read displayed text back** to decide what to do (`if (btn.textContent === 'Play')`): in another language it is
     translated. Keep the state in a variable or a `data-` attribute.
   - **Text the page shows only in a state the harvest cannot reach** (an error, a rare warning): write it as
     `VDI18N.t('Too many grains: {n} is the most', { n: MAX })`. The harvest reads the literal from the source. Guard it, because a stale cached
     library or a Node test that runs a slice of the demo has no `VDI18N`: `(typeof VDI18N === 'object' ? VDI18N.t('…') : '…')`.
   - **Canvas text you wrap into lines yourself**: translate the whole text first, then draw the lines inside
     `VDI18N.raw(() => { ... })`, so the pieces are neither looked up nor harvested (guard both with `window.VDI18N`).
     `measureText` is translated but never harvested, so measuring a label still measures what will be drawn.
4. A label that a longer language pushes out of its box: fix it with a style that only applies in another language,
   `:root[data-vd-lang] .my-label { white-space: normal; }`, so English stays exactly as it is.
5. Text that must never be translated (symbols, chemical formulas a student types, code): `translate="no"` on the element.
6. If the demo already has a translation, `node tools/i18n.cjs todo es demo/<demo>` lists the new strings to translate.

## Adding or updating a translation

1. `node tools/i18n.cjs todo es demo/<demo> > todo.json`, fill in the values (leave `{#}`, `{name}` and tags as they are; keep
   physics symbols, units and numbers exactly), then `node tools/i18n.cjs merge es demo/<demo> todo.json`.
2. A new language: make `demos/lib/i18n/<lang>/meta.json` and a `common.js` first.
3. `node tools/i18n.cjs index` (adds the page to the switch), `node tools/i18n.cjs check`, then look at the page with `?lang=<lang>`
   at 1280 and 400 px, light and dark.
4. Mark the work as reviewed only after a fluent speaker has read it: until then keep `draft` in `meta.json`.

## Rules

- English stays the source: change wording in the demo, harvest again, and update each translation (`check` lists keys that are
  no longer on the page).
- Physics stays exact in every language: same numbers, same symbols, same units (SI symbols are not translated), and the
  same stated approximations. A translation never adds or drops a caveat.
- Catalog files go through Pages' Liquid like everything else: the tool writes a brace next to a brace or a percent sign as
  `{`, so never type one by hand.
- Videos are not translated.
